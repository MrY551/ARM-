## 五、本轮修复记录

| 现象 | 根因 | 修复 |
|---|---|---|
| `mariadb-install-db` 报 `Could not find resolveip` | 组件包漏了 `resolveip` | 打包时带上 `resolveip`，并给它生成 wrapper |
| `libexec/mysqld: cannot open libpcre2-8.so.0` | `mariadb-install-db` 直接调用 `libexec/mysqld`，绕过 `bin` 包装 | 真实二进制改为 `*.bin`，`libexec/<name>` 放指回 wrapper 的软链，wrapper 用 `readlink -f` 解析自身 |
| mysql 客户端 `cannot open libedit.so.2` | 依赖闭包按 bundle 内文件名（`*.bin`）去 sysroot 查，查不到 | 依赖收集统一用 sysroot 原始路径 |
| `unknown variable 'log_error_verbosity=1'` | 该参数是 MySQL 5.7 的，MariaDB 10.x 没有 | 加 `loose-` 前缀 |
| `Ignoring user change to 'root' because the user was set to 'mysql'` 且初始化失败 | 未指定 `--defaults-file`，mysqld 读了宿主 `/etc/mysql/my.cnf` | `mariadb-install-db` 增加 `--defaults-file=<组件>/etc/my.cnf` |
| 多实例互相覆盖 `phpstudy-*.service` | unit 名固定 | 安装时检查 unit 指向目录，冲突则拒绝（退出码 3）与提示 |
| 合法路径 `/tmp/pstest` 被误判含空格 | bash `case` 的 `[[:space:]]` 按普通字符集解释 | 改逐字符白名单判断 |
| 路径校验 `exit` 不生效 | 函数在 `$(...)` 子 shell 里执行 | 改全局变量 `INSTALL_DIR_NORM` |
| Nginx 报 `Listen.conf:2` 语法错误 | Apache 语法的 `Listen 80` 被 nginx include | Nginx 侧不放该文件，端口写在 `server{}` |
| 改端口后 `server_name localhost;;` | awk 提取时带了分号 | `gsub(/;/,"")` |
| Apache `-t` 报 `Unsupported HTTP response code 509` | Apache 不认非标准码 | Apache 只声明标准码 |
| `LoadModule log_config_module` 失败 | Debian/Ubuntu 把该模块编进核心 | 按 `.so` 是否存在自动禁用并降级提示 |

## 八、FTP（vsftpd）

原版用 FileZilla Server 0.9.60（`app/Extensions/FTP0.9.60`），本机 FTP 服务，账号 + 站点目录 + 权限。
麒麟版用 vsftpd 3.0.3（Debian bullseye arm64）实现同一套语义，装在同一路径。

### 8.1 组件

```
[ OK ] FTP 服务 vsftpd 3.0.3 -> /tmp/ui/app/Extensions/FTP0.9.60
[ OK ] FTP 配置已生成（端口 12121，被动 32420-32440）
```

`lib/security/` 带 `pam_unix.so` + `pam_deny.so` + `pam_permit.so`，PAM 配置用绝对路径引用，
不依赖目标机 `libpam-modules` 的安装位置。`/etc/pam.d/xiaohuang-vsftpd` 内容：

```
auth     required /tmp/ui/app/Extensions/FTP0.9.60/lib/security/pam_unix.so
account  required .../pam_unix.so
session  required .../pam_unix.so
password required .../pam_unix.so
```

### 8.3 本轮修的坑

| 现象 | 根因 | 修复 |
|---|---|---|
| 登录返回 `530 Permission denied` | 账号建好前 `userlist` 为空，白名单拒绝；建账号未写白名单 | `ftp_user_add` 追加到 `userlist` 并重启服务 |
| 登录返回 `530 Login incorrect` | PAM 找不到 `pam_unix.so`（组件没带，系统路径在目标机不可知） | 组件打包时带上 `pam_unix/pam_deny/pam_permit` + 依赖库，PAM 配置写绝对路径 |
| 面板 FTP 卡片显示 MySQL 的版本/端口 | `status_json` 没有 `ftp` 分支，变量沿用上一个循环 | 加 `ftp)` 分支（`FTP vsftpd ${FTP_VER}`、`$FTP_PORT`） |

## 九、开机自启

安装默认 enable 哪些单元：nginx / php / mysql / ftp / panel = enabled，apache = disabled
（与 Nginx 共用 HTTP 端口，由 `switch` 决定谁开）。

```
$ xiaohuang autostart status
服务     开机自启 当前状态
nginx      enabled      stopped
apache     disabled     stopped
php        enabled      stopped
mysql      enabled      stopped
ftp        enabled      stopped

$ xiaohuang autostart status --json
[{"name":"nginx","enabled":"enabled","status":"stopped"}, …]
```

`switch` 会把自启一起切走（否则重启后旧的那个抢回端口）：

```
$ xiaohuang switch apache
[INFO] 停止当前 Web 服务器: nginx
[INFO] 启动目标 Web 服务器: apache
[ OK ] apache: systemctl start 成功
[INFO] 开机自启已切到 apache
[ OK ] Web 服务器已切换为 apache（端口 18099）

$ xiaohuang autostart status
nginx      disabled     stopped
apache     enabled      running
php        enabled      running
mysql      enabled      running
ftp        enabled      running
```

面板「设置 → 开机自启」五个芯片是同一套开关，实测：

```
POST op=autostart.off arg[name]=nginx → {"ok":true,"out":"[ OK ] nginx 已取消开机自启"}
POST op=autostart.on  arg[name]=nginx → {"ok":true,"out":"[ OK ] nginx 已设为开机自启"}
```

本轮修的坑：`svc_active` 本身会输出 `stopped` 并返回 1，调用处的 `|| echo stopped` 又追加一次，
导致状态列出现两行；`systemctl is-enabled` 对 disabled 同理。改成只取值、空值再兜底。
