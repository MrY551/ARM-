# 银河麒麟 ARM64 部署手册

**Xiao Huang 0.0.0.1Beta**（`kylin-arm64-1`）｜ 适用 银河麒麟 V10 aarch64，兼容 UOS / openEuler / Debian / Ubuntu arm64

这份是**交付方视角**：怎么把包铺到目标机、装完怎么验收、出问题往哪查。
使用方视角（怎么建站点、怎么建库、怎么排错）看随包分发的 `docs/用户手册.md`。

组件全部内置（Nginx 1.18.0 / Apache 2.4.62 / PHP 7.4.33 / MariaDB 10.5.23 / vsftpd 3.0.3，
aarch64 二进制 + 各自完整依赖库）。安装不联网、不读系统仓库、不要求目标机装过 LAMP。

---

## 1. 交付物

```
dist/
├── xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb    92 MB   dpkg 安装，组件内置
└── xiaohuang-kylin-arm64-0.0.0.1Beta.run          93 MB   自解压，参数最全
```

| | `.deb` | `.run` |
|---|---|---|
| 安装方式 | `dpkg -i` | `chmod +x` 后直接跑 |
| 参数 | 只能改 `/etc/xiaohuang/install.conf` 后重装 | 命令行全参数 |
| 组件来源 | `/usr/share/xiaohuang-installer/components/` | 包内 payload |
| 适合 | 批量铺、走内网源、要 `dpkg -l` 可查 | 单机交付、要定制端口/目录 |

两个包**装的是同一套东西**，同一个机器上只能装一个（单元名固定，第二个会被拒，退出码 3）。

校验：

```bash
sha256sum xiaohuang-kylin-arm64*
dpkg-deb --info xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb     # 看 Maintainer / Version
```

## 2. 部署前检查

| 项目 | 要求 | 检查命令 |
|---|---|---|
| 架构 | aarch64 | `uname -m` |
| 权限 | root | `id -u` |
| 初始化系统 | systemd（无则回退 pidfile） | `ps -p 1 -o comm=` |
| glibc | ≥ 2.17 | `ldd --version \| head -1` |
| 磁盘 | `/opt` 空余 ≥ 1.5 GB | `df -h /opt` |
| 依赖 | bash≥4.4 curl tar adduser coreutils | `bash --version \| head -1` |
| 端口 | 80/3306/9000/21/9002 没被占 | `ss -lnt \| grep -E ':(80\|3306\|9000\|21\|9002) '` |

一条命令过一遍：

```bash
bash -c '
echo "架构: $(uname -m)  用户: $(id -un)  init: $(ps -p 1 -o comm=)"
echo "glibc: $(ldd --version | head -1 | awk "{print \$NF}")"
echo "磁盘: $(df -h /opt | awk "NR==2{print \$4\" 可用\"}")"
for p in 80 3306 9000 21 9002; do
  ss -lnt 2>/dev/null | grep -q ":$p " && echo "端口 $p: 被占用" || echo "端口 $p: 空闲"
done'
```

**端口被占不等于装不了**：安装器会往上找空闲端口并写进清单，但交付时要确认业务方能否接受改端口。

## 3. 离线部署

### 3.1 介质准备

U 盘或内网共享，把 `dist/` 里要用的那个包拷过去。目标机不需要网络。

```bash
# 拷到目标机
cp xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb /root/
sha256sum /root/xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb   # 跟交付清单核对
```

### 3.2 deb 路径

```bash
sudo dpkg -i xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
sudo xiaohuang start
```

装到 `/opt/xiaohuang`，**装完不自动启动**（postinst 传的是 `--no-start`）。

要换目录或端口，先改配置再重装：

```bash
sudo nano /etc/xiaohuang/install.conf
# INSTALL_DIR=/data/xiaohuang
# INSTALL_ARGS="--no-start --http-port 8080"

sudo dpkg -P xiaohuang-kylin-arm64      # 先卸（保留数据用 -r）
sudo dpkg -i /root/xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
```

> 本包没注册 debconf，`dpkg-reconfigure` **不会**重读 `install.conf`，必须卸载重装。

### 3.3 run 路径

```bash
chmod +x xiaohuang-kylin-arm64-0.0.0.1Beta.run
sudo ./xiaohuang-kylin-arm64-0.0.0.1Beta.run --dir /data/xiaohuang --with-apache
```

### 3.4 安装器做的 8 步

1. 校验路径（空格/中文/相对路径 → 退出码 2）
2. 检查路径是否已有安装、单元名是否冲突（→ 退出码 3）
3. 建目录树（`app/` `bin/` `conf/` `logs/` `run/`）
4. 部署默认站点、13 个错误页、`app/panel/`
5. 解包内置组件到 `app/Extensions/`，写 `bin/<name>` 包装
6. 渲染配置（路径、端口落到实际值），初始化 MariaDB 数据目录
7. 注册 6 个 systemd 单元、设开机自启、部署会话式面板
8. 写 `xiaohuang.ini`、生成 `.integrity`、启动并自检

## 4. 安装参数

`.run` 可用全部参数；`.deb` 通过 `install.conf` 的 `INSTALL_ARGS` 传同样的串。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dir PATH` | `/opt/xiaohuang` | 必须纯英文绝对路径 |
| `--http-port PORT` | 80 | 被占自动找下一个 |
| `--db-port PORT` | 3306 | |
| `--ftp-port PORT` | 21 | 被占改 2121 |
| `--with-apache` | 关 | 额外装 Apache，默认只装 Nginx |
| `--no-db` `--no-ftp` `--no-php` | 都装 | 跳过对应组件 |
| `--no-start` | 自动启动 | 只装不起 |
| `--no-link` | 建软链 | 不建 `/usr/local/bin/xiaohuang` |
| `--force` | 关 | 组件起不来也继续 |
| `--offline DIR` | 包内 | 指定 `components/*.tar.gz` 目录 |
| `--supervisor MODE` | auto | `systemd` / `pidfile` |

## 6. 组件与自包含原理

组件目录里每个可执行文件都是两段式：

```
bin/nginx           sh 包装：
                    ROOT=$(readlink -f $0)/../
                    exec "$ROOT/lib/ld-linux-aarch64.so.1" \
                         --library-path "$ROOT/lib" \
                         "$ROOT/libexec/nginx.bin" "$@"
libexec/nginx.bin   真实 aarch64 ELF
lib/                该二进制的完整依赖闭包（含 libc.so.6、libssl、libpcre…）
libexec/nginx       → ../bin/nginx 的软链（组件内部脚本直接调 libexec 时也能走包装）
```

所以目标机 glibc 是 2.28 还是 2.34 都不影响，运行时不读 `/lib`、不读 `/usr/lib` 里的同库。

**重建组件**（想换版本或换来源时）：

```bash
# 方式一：从任意 arm64 sysroot 抽
./tools/gen-components.sh --sysroot /root/sysroot --out payload

# 方式二：在联网 arm64 机器上从系统仓库抽
sudo ./make-bundle.sh --out payload

# 然后重打安装包
./build.sh
```

`build.sh` 检测到 `payload/components/*.tar.gz` 就内置，没有则构建成在线安装版（依赖系统源）。

## 7. 系统集成

### 7.1 端口冲突

| 端口 | 用途 | 冲突时 |
|---|---|---|
| 80 | HTTP（Nginx/Apache 共用） | 自动 8080 |
| 443 | HTTPS 站点 | 与 HTTP 同端口体系，站点级 |
| 3306 | MariaDB | 自动 3307 |
| 9000 | PHP-FPM（仅 127.0.0.1） | 自动 9001 |
| 21 | FTP | 自动 2121 |
| 9002 | 面板（仅 127.0.0.1） | 自动 9003 |
| 30000-30020 | FTP 被动段 | 随 FTP 端口偏移 |

查占用并处理：

```bash
sudo xiaohuang ports
sudo xiaohuang kill --port 8080
sudo xiaohuang port nginx 8080     # 或者换个端口
```

### 7.2 服务接管

如果目标机本来跑着系统自带的 `nginx` / `apache2` / `php-fpm` / `mysql` / `mariadb`，
安装器会先 `stop` + `disable` 它们，避免抢端口。清单写在
`/opt/xiaohuang/.disabled-system-services`：

```bash
cat /opt/xiaohuang/.disabled-system-services
# 需要恢复时按里面的服务名手动 enable
sudo systemctl enable --now nginx
```

卸载**不会**自动恢复，这是有意的（避免把客户的环境改回去时出意外）。

### 7.3 防火墙

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --permanent --add-port=21/tcp
sudo firewall-cmd --permanent --add-port=30000-30020/tcp
sudo firewall-cmd --permanent --add-port=3306/tcp      # 只给内网/同机用就别开
sudo firewall-cmd --reload

# ufw
sudo ufw allow 80,443,21/tcp
```

**面板和 PHP-FPM 只监听 127.0.0.1，不需要放行。**
FTP 被动段必须放行，否则能登录但列不出目录。

### 7.4 SELinux / AppArmor

```bash
getenforce 2>/dev/null          # 麒麟/V10 若安装并启用了 SELinux
aa-status 2>/dev/null | head -3 # Debian 系
```

本包**没有附带 SELinux 策略**。如果 `getenforce` 返回 `Enforcing`，需要给
`/opt/xiaohuang/**` 打上正确的文件上下文，或者用 `semanage permissive -a` 放行相关域，
否则表现为组件起不来、配置读不到。

### 7.5 面板访问方式

面板是 `php -S` 起的本地服务，绑定 `127.0.0.1:9002`，**故意不对外**：

```bash
# 运维远程访问走 SSH 转发
ssh -L 9002:127.0.0.1:9002 root@目标机
# 本地浏览器开 http://127.0.0.1:9002/
```

初始密码在安装结束打印一次，哈希存 `xiaohuang.ini` 的 `PANEL_PASS_HASH`（MD5，文件 600）。
忘了就 `sudo xiaohuang panel passwd 新密码`，不需要登录。

## 8. 多实例限制

单元名固定（`xiaohuang-nginx/php/mysql/apache/ftp/panel`），同一台机器只能有一套在跑。
第二套装到别的目录会被 `check_unit_conflict` 拒绝，退出码 3。

要并行多个实例，只能换机器或跑容器——每个容器一套。

## 9. 开机自启

默认 enable：`nginx` `php` `mysql` `ftp` `panel`。Apache 默认不 enable（与 Nginx 抢同端口）。

```bash
sudo xiaohuang autostart              # 看状态
sudo xiaohuang autostart off          # 全部关掉
sudo xiaohuang autostart off nginx    # 只关一个
```

`xiaohuang switch apache` 会把自启一起切过去（disable 旧的、enable 新的），
否则重启后 Nginx 会把端口抢回来。

装完按顺序跑这 10 条，全部符合预期才算交付。

| # | 命令 | 预期 |

| 4 | `sudo xiaohuang verify` | `全部与安装时一致`，退出码 0 |

| 6 | `sudo xiaohuang db list` | 能连上，列出 information_schema 等 |

再抽一条端到端：

```bash
sudo xiaohuang site add test.local /opt/xiaohuang/app/WWW/test

sudo xiaohuang site del test.local
sudo xiaohuang hosts del test.local
```

## 11. 升级与回滚

**升级**：同路径装新版本，站点和数据库保留。

```bash
sudo dpkg -i xiaohuang-kylin-arm64_新版本_arm64.deb
# 或
sudo ./xiaohuang-kylin-arm64-新版本.run --dir /opt/xiaohuang
```

版本号规则：`0.0.0.1Beta` 之后要发 `0.0.0.2` 或 `0.0.0.2Beta`。
**不要发 `0.0.0.1`**——dpkg 认为它比 `0.0.0.1Beta` 旧，不会升级（已实测）。

**回滚**：

```bash
sudo xiaohuang uninstall            # 卸程序，保留 WWW 和 MySQL data
sudo ./xiaohuang-kylin-arm64-旧版本.run --dir /opt/xiaohuang
```

升级前建议先备份：

```bash
sudo systemctl stop xiaohuang-mysql
sudo tar czf /root/xiaohuang-backup-$(date +%F).tgz \
     /opt/xiaohuang/app/WWW /opt/xiaohuang/app/Extensions/MySQL*/data \
     /opt/xiaohuang/xiaohuang.ini
sudo systemctl start xiaohuang-mysql
```

## 12. 防篡改与署名

每个包 build 时生成唯一 `BUILD_ID`，写进 `xiaohuang.ini`，CLI 和面板都显示。
安装完成时对 15 个文件算 SHA-256 存到 `.integrity`：

```bash
$ sudo xiaohuang verify
[INFO] 校验 15 个文件…
[ OK ] 全部与安装时一致
构建指纹: 202610251814-26fcea27

# 被改过
$ sudo xiaohuang verify
[WARN] 以下文件被改过：
       bin/xiaohuang: FAILED
[WARN] 不是你自己改的，就重新装一遍官方包        # 退出码 1
```

署名点在 6 处（CLI 版本行、面板页脚、关于页、systemd Description、手册、LICENSE）。
改动后对外分发，按 `LICENSE` 要求须标注「非官方修改版」。

## 13. 排错入口

**先跑这三条**：

```bash
sudo xiaohuang status          # 服务状态 + HTTP 自检
sudo xiaohuang verify          # 文件完整性
sudo systemctl status xiaohuang-nginx --no-pager -n 30
```

**日志位置**：

| 组件 | 路径 |
|---|---|
| Nginx | `app/Extensions/Nginx1.18.0/logs/{error,access}.log` |
| Apache | `app/Extensions/Apache2.4.62/logs/{error,access}_log` |
| PHP-FPM | `app/Extensions/php/php7.4.33/log/php-fpm.log` |
| MariaDB | `app/Extensions/MySQL10.5.23/log/error.log` |
| FTP | `app/Extensions/FTP0.9.60/logs/vsftpd.log` |
| 面板 | `journalctl -u xiaohuang-panel -n 50` |
| 安装器 | 安装时的 stdout，或 `journalctl -u xiaohuang-*` |

**退出码**：

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | |
| 2 | 路径含中文/空格/非白名单字符 | 换纯英文路径 |
| 3 | 路径已有安装，或单元名冲突 | 换目录 / 先卸载 |
| 4 | 架构不是 aarch64 | 换包 |
| 5 | 非 root | `sudo` |
| 6 | 组件缺失、依赖不全 | 看安装器输出 |
| 7 | 服务启动失败 | `xiaohuang log <组件>` |

具体症状（502 / 403 / 530 / 数据库连不上 / 面板打不开 / 容器无 systemd）看
`docs/用户手册.md` 第 6 章，那里有 12 条对应处置。
