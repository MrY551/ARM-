# Xiao Huang 常见问题与排错手册

Xiao Huang 0.0.0.1Beta ｜ 银河麒麟 ARM64

按你遇到问题的阶段查，每条都是「现象 → 原因 → 命令 → 怎么算好了」。

---

## 0. 先跑这个

一条命令把该看的全打出来，比逐条猜快得多：

```bash
sudo bash /opt/xiaohuang/xh-diag.sh
```

如果没这个文件（旧包），从压缩包里拷一个进来，或者直接跑：

```bash
sudo xiaohuang status
sudo xiaohuang verify
sudo systemctl status xiaohuang-nginx --no-pager -l
sudo journalctl -u xiaohuang-nginx -n 40 --no-pager
```

后面所有小节都会告诉你「看哪一段」。

## 1. 安装阶段

### 1.1 dpkg 报「依赖于 curl，然而未安装」

**原因**：旧包的 `Depends` 里写了 curl。新包已经改成只依赖 `bash` 和 `tar`。

**先装上**（不换包）：

```bash
sudo dpkg -i --force-depends xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
sudo xiaohuang start
```

装完 `status` 里 HTTP/PHP 两行可能显示 `000`，不影响使用——那只是没 curl 取状态码。

**根治**：换新包，或者装个 curl：`sudo apt install curl`。

---

### 1.2 图形安装器双击报 `local variable 'deb' referenced before assignment`

**原因**：麒麟自带的图形安装器（`kylin-installer`）的 Python bug，跟包内容无关。同一个包命令行装完全正常。

**绕过**：

```bash
sudo dpkg -i xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
```

要图形界面就装 gdebi：

```bash
sudo apt install gdebi
sudo gdebi xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
```

压缩包里另有一个纯数字版本号的兼容包（`0.0.0.1-1`），双击成功率高一些，但根子还是安装器的问题。

---

### 1.3 退出码对照

| 退出码 | 意思 | 怎么处理 |
|---|---|---|
| 0 | 成功 | |
| 2 | 安装路径含中文/空格/非法字符 | 换纯英文路径，如 `/opt/xiaohuang` |
| 3 | 路径下已有安装，或单元名冲突 | 先卸载，或换目录 |
| 4 | 架构不是 aarch64 | 换包 |
| 5 | 不是 root | `sudo` |
| 6 | 组件缺失、依赖不全 | 看安装器输出上面几行 |
| 7 | 服务启动失败 | 跳到第 2 节 |

---

### 1.4 路径不对被拒

路径只能是**纯英文、数字、`._/+@-`**，不能有空格、中文，必须绝对路径。

```bash
# 对
/opt/xiaohuang      /data/xiaohuang      /usr/local/xh

# 错
/opt/xiao huang     有空格
/opt/小黄            有中文
xiaohuang            相对路径
```

---

### 1.5 提示磁盘不足

```bash
df -h /opt
```

解包后约占 700 MB，安装过程还需要约 200 MB 临时空间。不够就先清：

```bash
sudo apt clean
sudo journalctl --vacuum-size=100M
```

## 2. 装完服务起不来

### 2.1 nginx 起不来（最常见）

`systemctl` 只会说「control process exited with error code」，真正的错因在 nginx 自己的输出里：

```bash
sudo /opt/xiaohuang/app/Extensions/Nginx1.18.0/bin/nginx -t \
  -c /opt/xiaohuang/app/Extensions/Nginx1.18.0/conf/nginx.conf \
  -p /opt/xiaohuang/app/Extensions/Nginx1.18.0
```

（安装目录不是 `/opt/xiaohuang` 的话，把路径换掉。）

输出里以 `[emerg]` 开头的那行就是病根。对照下表：

| `[emerg]` 内容 | 原因 | 解决 |
|---|---|---|
| `setrlimit(RLIMIT_NOFILE, 100000) failed` | 系统文件句柄硬限制低于 100000 | 新包已修；旧包见下方「手动修 nofile」 |
| `bind() to 0.0.0.0:80 failed (98: Address already in use)` | 80 端口被占 | `ss -lntp \| grep ':80 '` 看是谁，然后 `sudo xiaohuang port nginx 8080` |
| `open() ".../conf/vhosts/*.conf" failed` | vhosts 目录丢失 | `sudo xiaohuang repair` |
| `getpwnam("www-data") failed` | 运行用户不存在 | 见下方「运行用户」 |
| `open() ".../logs/nginx.pid" failed (13: Permission denied)` | 目录权限不对 | `sudo chown -R root:root /opt/xiaohuang/app/Extensions/Nginx*/logs` |
| `invalid PID number` | 上次异常退出留下坏 pid 文件 | `sudo rm -f /opt/xiaohuang/app/Extensions/Nginx*/logs/nginx.pid` |

**手动修 nofile**（旧包）：

```bash
sudo sed -i '/worker_rlimit_nofile/d' /opt/xiaohuang/app/Extensions/Nginx1.18.0/conf/nginx.conf
sudo sed -i 's/worker_connections  40960/worker_connections  10240/' /opt/xiaohuang/app/Extensions/Nginx1.18.0/conf/nginx.conf
sudo sed -i 's/^LimitNOFILE=.*/LimitNOFILE=65535/' /etc/systemd/system/xiaohuang-nginx.service
sudo systemctl daemon-reload
sudo systemctl restart xiaohuang-nginx
```

**运行用户**：

```bash
grep '^user' /opt/xiaohuang/app/Extensions/Nginx1.18.0/conf/nginx.conf
id www-data
```

如果没有 `www-data`，改成存在的用户：

```bash
sudo sed -i 's/^user .*/user nobody;/' /opt/xiaohuang/app/Extensions/Nginx1.18.0/conf/nginx.conf
sudo systemctl restart xiaohuang-nginx
```

**验证**：

```bash
sudo systemctl is-active xiaohuang-nginx     # 输出 active
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/   # 输出 200
```

---

### 2.2 PHP-FPM 起不来

```bash
sudo /opt/xiaohuang/app/Extensions/php/php7.4.33/bin/php-fpm -t \
  -c /opt/xiaohuang/app/Extensions/php/php7.4.33/etc \
  -y /opt/xiaohuang/app/Extensions/php/php7.4.33/etc/php-fpm.conf
```

常见：

- `bind() to 127.0.0.1:9000 failed` —— 端口被占，`sudo xiaohuang port php 9100`（会同时改 nginx 的 fastcgi_pass）
- `ERROR: Unable to create the PID file` —— 权限问题，`sudo xiaohuang repair`
- 扩展加载失败 —— 看 `sudo xiaohuang ext list`，把报错的扩展关掉：`sudo xiaohuang ext disable 扩展名`

---

### 2.3 MySQL / MariaDB 起不来

```bash
sudo xiaohuang log mysql | tail -40
```

| 报错 | 原因 | 解决 |
|---|---|---|
| `Can't create/write to file ... (Errcode: 13)` | data 目录权限 | `sudo chown -R root:root /opt/xiaohuang/app/Extensions/MySQL*/` |
| `InnoDB: Unable to lock ./ibdata1` | 上次没干净退出 | `sudo rm -f /opt/xiaohuang/app/Extensions/MySQL*/data/ib_logfile*` 再起 |
| `unknown variable 'log_error_verbosity'` | 用了 MySQL 的写法跑 MariaDB | 新包用 `loose-` 前缀；旧包手动加 `loose-` |
| `Plugin 'unix_socket' is not loaded` | root 认证方式问题 | `sudo xiaohuang db passwd root` 重设 |

**数据目录彻底重建**（会丢数据）：

```bash
sudo systemctl stop xiaohuang-mysql
sudo cp -a /opt/xiaohuang/app/Extensions/MySQL10.5.23/data \
          /opt/xiaohuang/app/Extensions/MySQL10.5.23/data.bak
sudo rm -rf /opt/xiaohuang/app/Extensions/MySQL10.5.23/data
sudo xiaohuang repair
sudo systemctl start xiaohuang-mysql
```

---

### 2.4 FTP 起不来

```bash
sudo xiaohuang log ftp | tail -20
ss -lnt | grep ':21 '
```

- `500 OOPS: cannot change directory` —— 站点目录不存在或权限不对
- `500 OOPS: vsftpd: refusing to run with writable root inside chroot` —— 新包已加 `allow_writeable_chroot=YES`
- 端口被占 —— `sudo xiaohuang ftp port 2121`

---

### 2.5 面板起不来

```bash
systemctl status xiaohuang-panel --no-pager -l
ss -lnt | grep 9002
```

- 服务没起：`sudo systemctl start xiaohuang-panel`
- 端口没监听：`sudo journalctl -u xiaohuang-panel -n 40`，多半是 PHP 起不来（见 2.2）
- 端口不是 9002：`sudo xiaohuang panel url` 查真实地址

## 3. 网站访问不了

### 3.1 502 Bad Gateway

PHP-FPM 挂了，或者端口对不上。

```bash
sudo xiaohuang status | grep php          # 是不是 running
sudo xiaohuang port php 9000              # 会同时改 php-fpm 和 nginx 的 fastcgi_pass
sudo xiaohuang log php | tail -20
```

---

### 3.2 403 Forbidden

目录权限或 index 文件问题。

```bash
ls -ld /opt/xiaohuang/app/WWW
sudo chown -R www-data:www-data /opt/xiaohuang/app/WWW
sudo chmod -R 755 /opt/xiaohuang/app/WWW
```

站点目录属主必须是 `www-data`（`sudo xiaohuang status` 里会显示运行用户）。

---

### 3.3 404 Not Found

- 站点根目录里没有 `index.html` / `index.php`
- vhost 指向的目录和你想的不一样：`sudo xiaohuang site list`

---

### 3.4 500 Internal Server Error

PHP 报错。看：

```bash
sudo xiaohuang log nginx
sudo tail -50 /opt/xiaohuang/logs/site-*-error.log
```

临时打开错误显示（排完记得关）：

```bash
sudo sed -i 's/^display_errors = .*/display_errors = On/' /opt/xiaohuang/app/Extensions/php/php7.4.33/etc/php.ini
sudo systemctl restart xiaohuang-php
```

---

### 3.5 PHP 页面变成下载

nginx 没把 `.php` 交给 FPM。

```bash
sudo xiaohuang repair
sudo systemctl restart xiaohuang-nginx xiaohuang-php
```

---

### 3.6 浏览器一直转圈

```bash
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' --max-time 10 http://127.0.0.1/
```

- 超时：nginx 卡住，看 `sudo xiaohuang log nginx`
- 通了但浏览器不通：防火墙（见第 7 节）

---

### 3.7 IP 能开、域名打不开

DNS 没解析到这台机器，或者本地 hosts 没写。

```bash
ping -c1 你的域名
sudo xiaohuang hosts add 你的域名      # 写本机 hosts，仅本机有效
```

---

### 3.8 HTTPS 站点打不开

```bash
sudo xiaohuang site list                       # 看 SSL 是不是「已启用」
ls -l /opt/xiaohuang/app/Extensions/Nginx*/conf/ssl/
```

证书或私钥路径错、私钥权限太松（nginx 拒绝加载）都会失败：

```bash
sudo chmod 600 /opt/xiaohuang/app/Extensions/Nginx*/conf/ssl/*.key
sudo systemctl restart xiaohuang-nginx
```

撤销：

```bash
sudo xiaohuang site ssl-del 你的域名
```

## 4. 面板

### 4.1 面板打不开

面板只监听 `127.0.0.1`，从别的机器直接访问是打不开的。

```bash
# 在你自己电脑上
ssh -L 9002:127.0.0.1:9002 root@服务器IP
# 然后本地浏览器开 http://127.0.0.1:9002/
```

---

### 4.2 登录不了 / 密码忘了

```bash
sudo xiaohuang panel passwd 新密码
```

不需要登录，root 直接改。改完刷新页面。

登录一直转圈：`sudo systemctl restart xiaohuang-panel`。

---

### 4.3 页面提示「接口返回了网页而不是数据」

登录过期了。刷新页面重新登录即可。

如果刷新还这样，说明 PHP 会话目录写不进去：

```bash
sudo ls -ld /opt/xiaohuang/app/Extensions/tmp/tmp
sudo chown -R www-data:www-data /opt/xiaohuang/app/Extensions/tmp
sudo systemctl restart xiaohuang-panel
```

---

### 4.4 日志页空白或显示「该日志还没有内容」

那个服务确实还没产生日志。先确认它有在跑：

```bash
sudo xiaohuang status
curl -s -o /dev/null http://127.0.0.1/     # 触发一次访问，access 日志就有了
```

命令行对照：

```bash
sudo xiaohuang log nginx
sudo xiaohuang log access
sudo xiaohuang log php
sudo xiaohuang log ftp
sudo xiaohuang log panel
```

---

### 4.5 点了按钮没反应

F12 看 Console 有没有红色报错。最常见是登录过期（见 4.3），其次是操作本身失败（会弹红色提示，内容就是要看的原因）。

---

### 4.6 目录浏览打不开某个目录

面板只允许浏览真实存在的目录，`/proc`、`/sys`、`/dev`、`/run` 是拒绝的（没意义且会卡）。

## 5. 数据库

### 5.1 连不上

```bash
sudo xiaohuang status | grep mysql
ss -lnt | grep 3306
sudo xiaohuang db passwd root          # 密码不对时重设
```

### 5.2 PHP 报 `Access denied for user 'root'@'localhost'`

密码不对，或者用了 `localhost`（走 socket）但 socket 路径不对。改用 `127.0.0.1`：

```php
$pdo = new PDO('mysql:host=127.0.0.1;port=3306;dbname=test', 'root', 'root');
```

### 5.3 PHP 报 `could not find driver`

mysqli / pdo_mysql 没启用：

```bash
sudo xiaohuang ext enable mysqli
sudo xiaohuang ext enable pdo_mysql
```

### 5.4 导入大 SQL 失败

```bash
sudo /opt/xiaohuang/app/Extensions/MySQL10.5.23/bin/mysql \
  -uroot -proot -h127.0.0.1 -P3306 库名 < big.sql
```

`max_allowed_packet` 太小会断，改 `/opt/xiaohuang/app/Extensions/MySQL*/etc/my.cnf` 加 `max_allowed_packet=256M` 再重启。

### 5.5 忘记数据库 root 密码

```bash
sudo xiaohuang db passwd 新密码
```

## 6. FTP

### 6.1 530 Login incorrect

密码错，或账号不在白名单：

```bash
sudo xiaohuang ftp list
cat /opt/xiaohuang/app/Extensions/FTP0.9.60/etc/userlist
sudo xiaohuang ftp passwd 账号 新密码
```

### 6.2 530 Permission denied

账号没写进白名单，重新加一次：

```bash
sudo xiaohuang ftp add 账号 目录 密码
```

### 6.3 能登录但列不出目录

被动模式端口被防火墙挡了。

```bash
grep -E 'pasv_(min|max)_port' /opt/xiaohuang/app/Extensions/FTP0.9.60/etc/vsftpd.conf
sudo firewall-cmd --permanent --add-port=30000-30020/tcp
sudo firewall-cmd --reload
```

实在不行临时用主动模式：客户端里关掉 PASV。

### 6.4 上传了文件但网站看不到

属主问题：

```bash
ls -l /opt/xiaohuang/app/WWW/你的站
sudo chown -R www-data:www-data /opt/xiaohuang/app/WWW/你的站
```

## 7. 端口与防火墙

### 7.1 开哪些端口

| 端口 | 用途 | 要不要对外 |
|---|---|---|
| 80 | HTTP | 要 |
| 443 | HTTPS | 要 |
| 21 | FTP | 要 |
| 30000-30020 | FTP 被动 | 要 |
| 3306 | MySQL | 只给内网/本机 |
| 9000 | PHP-FPM | **不要**（只听 127.0.0.1） |
| 9002 | 面板 | **不要**（只听 127.0.0.1，用 SSH 转发） |

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --permanent --add-port=21/tcp
sudo firewall-cmd --permanent --add-port=30000-30020/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports

# ufw
sudo ufw allow 80,443,21/tcp
sudo ufw status
```

### 7.2 端口被占

```bash
sudo xiaohuang ports                 # 看谁占着
sudo xiaohuang kill --port 8080      # 直接杀掉（看清楚再敲）
sudo xiaohuang port nginx 8090       # 或者换端口
```

## 8. 彻底卸载与重装

### 8.1 卸载

**保留网站和数据库**（换版本、修问题时用这个）：

```bash
sudo xiaohuang uninstall
```

**全删**（换机器、重来）：

```bash
sudo xiaohuang uninstall --purge
```

用 deb 装的：

```bash
sudo dpkg -r xiaohuang-kylin-arm64     # 保留数据
sudo dpkg -P xiaohuang-kylin-arm64     # 连配置一起删
```

### 8.2 卸载后要手动清的

```bash
# FTP 账号是系统用户，卸载不会自动删
sudo userdel -r ftp_账号名

# 残留的 systemd 单元（正常情况下已经删了）
sudo ls /etc/systemd/system/xiaohuang-* 2>/dev/null
sudo rm -f /etc/systemd/system/xiaohuang-*.service
sudo systemctl daemon-reload

# hosts 里加过的域名
sudo xiaohuang hosts del 你的域名
```

**验证干净了**：

```bash
ls -d /opt/xiaohuang 2>/dev/null || echo "目录已删"
ls /etc/systemd/system/xiaohuang-* 2>/dev/null || echo "单元已清"
ss -lnt | grep -E ':(80|3306|9000|21|9002) ' || echo "端口已释放"
```

### 8.3 重装

```bash
sudo dpkg -i xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
sudo xiaohuang start
sudo xiaohuang status
```

如果报「系统里已注册另一套 Xiao Huang 服务」，说明旧单元没清干净：

```bash
sudo rm -f /etc/systemd/system/xiaohuang-*.service
sudo systemctl daemon-reload
sudo dpkg -i xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
```

### 8.4 换安装目录

```bash
# run 直接指定
sudo ./xiaohuang-kylin-arm64-0.0.0.1Beta.run --dir /data/xiaohuang

# deb 要改配置后重装
sudo nano /etc/xiaohuang/install.conf     # INSTALL_DIR=/data/xiaohuang
sudo dpkg -P xiaohuang-kylin-arm64
sudo dpkg -i xiaohuang-kylin-arm64_0.0.0.1Beta_arm64.deb
```

### 8.5 换端口重装

```bash
sudo ./xiaohuang-kylin-arm64-0.0.0.1Beta.run \
  --dir /opt/xiaohuang --http-port 8080 --db-port 3307 --ftp-port 2121
```

装完还能改，不用重装：

```bash
sudo xiaohuang port nginx 8080
sudo xiaohuang port php 9100
sudo xiaohuang port mysql 3307
sudo xiaohuang ftp port 2121
```

## 9. 从旧版升级

```bash
# 先备份
sudo systemctl stop xiaohuang-mysql
sudo tar czf /root/xh-backup-$(date +%F).tgz \
     /opt/xiaohuang/app/WWW \
     /opt/xiaohuang/app/Extensions/MySQL*/data \
     /opt/xiaohuang/xiaohuang.ini
sudo systemctl start xiaohuang-mysql

# 卸载（保留数据）再装新包
sudo xiaohuang uninstall
sudo dpkg -i xiaohuang-kylin-arm64_新版本_arm64.deb
sudo xiaohuang start
sudo xiaohuang verify
```

版本号排序注意：`0.0.0.1Beta` 之后要发 `0.0.0.2` 或 `0.0.0.2Beta`。
发 `0.0.0.1` 的话 dpkg 认为它更旧，不会升级。

## 10. 文件位置速查

```
/opt/xiaohuang/
├── xiaohuang.ini              清单：端口、版本、root 密码、面板哈希、构建指纹
├── .integrity                 15 个文件的校验和（xiaohuang verify 用）
├── LICENSE  BUILD  docs/用户手册.md
├── app/
│   ├── WWW/                   站点根目录
│   ├── panel/                 管理面板源码
│   └── Extensions/
│       ├── Nginx1.18.0/       conf/nginx.conf  logs/  conf/vhosts/
│       ├── Apache2.4.62/      conf/httpd.conf  modules/  logs/
│       ├── php/php7.4.33/     etc/php.ini  etc/php-fpm.conf  lib/php/20190902/
│       ├── MySQL10.5.23/      etc/my.cnf  data/  log/error.log
│       └── FTP0.9.60/         etc/vsftpd.conf  etc/userlist  logs/
├── bin/xiaohuang              命令行（软链 /usr/local/bin/xiaohuang）
├── logs/                      各站点和组件的日志
└── run/                       pid 和 socket
```

**日志对照**：

| 想看什么 | 文件 | 命令 |
|---|---|---|
| 站点访问 | `logs/site-*-access.log` | `sudo xiaohuang log access` |
| 站点报错 | `logs/site-*-error.log` | `sudo xiaohuang log nginx` |
| PHP | `logs/php-fpm.log` | `sudo xiaohuang log php` |
| 数据库 | `app/Extensions/MySQL*/log/error.log` | `sudo xiaohuang log mysql` |
| FTP | `app/Extensions/FTP*/logs/vsftpd.log` | `sudo xiaohuang log ftp` |
| 面板 | journald | `sudo xiaohuang log panel` |
| 服务本身 | journald | `sudo journalctl -u xiaohuang-nginx -n 50` |
